# M5 承载力与乡村分流 · 验收记录

> 验收日期：2026-09-27 · 结论：**通过（后端 + 前端，两轮）**
> 模块范围（第一轮）：`scripts/gen_synthetic.py`（合成客流）→ `db/V8__m5_ops.sql`（四张表）→ 导入器接入 → 规则引擎 → 运营接口 → 前端接真实数据 + 管理端「风险与工单」页
> 模块范围（第二轮，同日续做）：`db/V9__m5_diversion.sql`（第 5 张表 `diversion_notice`）→ `DiversionAdvisor`（候选排序纯函数）→ 运营端生成 / 编辑 / 发布 / 撤下 → 游客端首页告警条 + 详情页 banner。**第二轮的设计决定与验收见「八」**
> 模块目标（`docs/模块划分与依赖.md` 第 45 行）：**把"热点景区超载 + 周边乡村闲置"从一句主张变成一套可判、可处置、可回看的机制**。

## 一、模块职责边界

**做**：
- 合成客流与经营日度统计（42 个资源点 × 60 天 = 2520 行），带 `synthetic=true` 声明；
- 六条可配置阈值的风险规则，判定与阈值**分离**（判定在代码、阈值在表里）；
- 风险事件 → 工单 → 指派 → 处置 → 闭环，含幂等重扫与状态保持；
- 游客端承载显示（探索 / 行程 / 详情）从仿真常量换成真实接口；
- 详情页「分流建议」从"空间上可承接"升级为"**当前**可承接"。

**不做**：真实客流接入（没有数据源）、单点小时级客流、风险事件的自动建单、
把模型接进判定链路（那是 M7 的 `POST /api/ai/analyze/ops`；**落地时路径改成
`POST /api/admin/ops/analyze`** —— 返回的是运营数据的解读，不能放在 permitAll 的
`/api/ai/**` 下，见 `docs/验收记录-M7.md`「三、第 1 条」）、
资源点级口碑评分（`poi` 表没有评分列，属 M6 评价域，见「五、已知缺口」）。

**三条设计红线没有被触碰**：
1. **不是电商** —— M5 不新增任何商品入口，风险建议里出现的乡村点只跳 `/poi/{id}`；
2. **不是聊天机器人** —— 规则判定全程确定性，**没有一步经过模型**。界面上凡是
   这一块的地方都**不写"AI"**（本轮专门做了口径审计，见「四、第 5 条」）；
3. **不改 M1–M4 已验收的接口** —— 新增的 `/api/stats/**` 与 `/api/admin/ops/**`
   是全新路径，`SecurityConfig` 显式加白名单；M1 的 `poi_relation`、M2 的体验与产品
   一行未动。

**一条不可违反的边界（与 M8/M9 同源）**：四张表里只有 `poi_visit_stats` 带
`city_code` —— 它是**数据包的一部分**，重启要重灌。`risk_rule`（系统配置）、
`risk_event` / `work_order`（运行期业务事实）都不带，否则运营调过的阈值、
建过的工单会随重启消失。

## 三、接口定义

### 游客端（公开，未登录可访问）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/stats/pois` | 全部资源点的当日承载。一次取全（42 条 < 4 KB），前端按 `poi_id` 查 |
| GET | `/api/diversion-notices` | **第二轮**：当前**生效**的分流公告（`status=PUBLISHED` **且** `expire_at > now()`）。过期过滤在**查询侧**，不靠定时任务 —— 定时任务没跑时公告照样会消失，不然"过期"这个语义取决于调度器有没有启动 |

**为什么只放行 GET**：规则扫描、建单、处置全在 `/api/admin/**` 下。这里若不限定方法，
等于把"手动触发规则扫描"也开给了游客。

**为什么给的是承载率而不是原始客流**：错峰引导的价值在于**还没到访的人**能看到，
要求登录等于把它从"公共信息"降级成"会员服务"。但只给聚合后的比值，原始客流
（`visitors` / `review_count` 等）只在运营端暴露。

### 运营端（`/api/admin/**`，`hasRole("OPERATOR")`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/ops/snapshot` | 驾驶舱快照（6 组图表的数据） |
| POST | `/api/admin/ops/scan` | 手动重跑规则扫描，返回命中条数。**幂等** |
| GET | `/api/admin/risks` | 风险事件列表。`?status=` `?level=` `?district=` 可组合 |
| GET | `/api/admin/risks/{id}` | 风险事件详情 |
| POST | `/api/admin/risks/{id}/work-order` | 一键建单。同一条事件只能建一张，重复报 8003 |
| GET | `/api/admin/work-orders` | 工单列表。`?status=` 可选 |
| PATCH | `/api/admin/work-orders/{id}` | 改派 / 置处置中 / 填反馈完结 |
| POST | `/api/admin/risks/{id}/notice` | **第二轮**：生成公告草稿（候选由 `DiversionAdvisor` 算，快照落库）。同一条事件已有**未过期**公告时报 8011；**已过期时反而放行** —— 复用同一行（id 不变）重算候选、换发新编码、回到草稿。这是 8015 那句"请重新生成"的出路 |
| GET | `/api/admin/diversion-notices` | 公告列表，**四态齐全**（草稿 / 已发布 / 已撤下 / 已过期），过期的也留着不静默消失 |
| PATCH | `/api/admin/diversion-notices/{id}` | 改文案 / 发布 / 撤下。发布时**重算失效时间**并记 `published_by` |

**路径为什么挂在 `/api/admin/**` 而不是方案里写的 `/api/ops/**`**：
`SecurityConfig.ADMIN_PREFIX` 把整个前缀统一交给 `hasRole("OPERATOR")`，
新增运营接口不用逐个标注权限。方案第 16 节写的是 `/api/ops/snapshot`，
那是设计阶段的草案；实施以 M8 定下的前缀约定为准（模块文档的"扩展点"一节也是这么写的）。
**漏配权限的后果是"访问不了"，而不是"游客也能看到运营数据"。**

新增错误码（`common/ErrorCode.java` 8xxx 段）：

| 码 | 文案 |
|---|---|
| 8001 | 风险事件不存在或已被清理 |
| 8002 | 工单不存在 |
| 8003 | 该风险事件已经建过工单，请到工单列表查看 |
| 8004 | 工单状态不合法，只支持处置中或已完结 |
| 8005 | 完结工单前请填写处置反馈 |
| 8010 | 分流公告不存在 |
| 8011 | 该风险事件已经生成过分流公告，请到公告列表查看 |
| 8012 | 公告状态不合法，只支持发布或撤下 |
| 8013 | 周边暂无可承接的资源点，无法生成分流公告 |
| 8014 | 请填写公告标题 |
| 8015 | 公告已过期，请重新生成后再发布 |

## 四、关键设计验证

### 1. 合成数据的移植保真度：42/42 逐值一致

`gen_synthetic.py` 要把前端 mock 的确定性伪随机（`web/src/mock/hash.ts` 的
FNV-1a + fmix32）搬到 Python，而两者在数字语义上**不一样**：

| 差异 | JS | Python | 处理 |
|---|---|---|---|
| 整数溢出 | 32 位自动回绕 | 任意精度 | `_to_int32()` 显式截断 |
| `Math.imul` | 32 位乘法 | 无对应 | `_imul()` 手工模拟 |
| `>>>` | 无符号右移 | 无对应 | `_ushr()` |
| `toFixed` | 半上舍入 | `round()` 是银行家舍入 | `decimal.ROUND_HALF_UP` |
| `charCodeAt` | UTF-16 码元 | `ord()` 是码点 | `_utf16_units()` |

**验证方式**：把真实的 TS 模块用 esbuild 打包成 ESM 跑一遍，与 Python 输出逐行对比。

```
esbuild --bundle --platform=node --format=esm web/src/mock/hash.ts → ref_stats.bundle.mjs
node ref_stats.bundle.mjs > ref_stats.tsv   （42 行）
python scripts/gen_synthetic.py --verify > py_stats.tsv
diff → 0 处不匹配
```

> 第一轮对比出现过 12 处不匹配，**全部集中在 RURAL_SPOT**。核对后确认是
> **有意的区间调整**而非移植错误（见下条），用 JS 侧的原始区间重跑后为 0 差异。

### 2. 让数据去适配方案，而不是放宽阈值去适配数据

旧 mock 的 `RURAL_SPOT` 区间是 `[0.22, 0.67]` —— **下限 22% 永远够不到
"乡村承载 < 20%" 这条规则**，规则 4（RURAL_IDLE）在设计上不可能触发。
旧 mock 通过把判定放宽到 `scenic≥75 && rural≤40` 来掩盖这一点。

本轮的选择是**让数据覆盖到标准要求的区间**：`RURAL_SPOT` 改为 `[0.07, 0.58]`，
南郑区的乡村平均承载降到 17.5%（阈值 20%，留 2.5pp 余量）。
规则本身保持方案第 15 节的原口径。

| REVIEW_SURGE | 2 | |

### 4. 幂等与"状态不被重扫覆盖"（实测）

规则引擎可以被反复触发（启动时一次、运营手动一次）。三条关键性质**逐条实测**：

| 场景 | 期望 | 实测 |
|---|---|---|
| 重启服务后重扫 | 不新增重复事件 | `新增 0 / 刷新 17`，总数仍 17 ✅ |
| 手动 `POST /ops/scan` | 同上 | 命中 17，总数不变 ✅ |
| 已建单的事件重扫 | `status` 与 `work_order_id` **不被覆盖回 OPEN** | 保持 `CLOSED` / `work_order_id=1`，指标值刷新 ✅ |
| 幽灵事件（数据已不支持、且未建单） | 清掉 | 造 2 条假事件：无工单的被清、挂工单的保留 ✅ |

**为什么保留已建单的**：那已经是运营动作的记录（谁在处置、处置到哪一步），
不是"当前的发现"，不能因为重扫就抹掉。

### 5. 口径审计：改了数据源含义后，回头搜"过度声称"

M5 把承载数字从"按 id 派生的伪随机常量"换成了"当日合成统计"，
数字的含义变了，于是把全站的说法回头核了一遍。**共改 8 处**：

| 位置 | 原文 | 改为 | 理由 |
|---|---|---|---|
| `Dashboard.vue` KPI | 今日**全市**到访 | 今日**核心景区**到访 | 该值只含 SCENIC（84,529），不含乡村/餐饮/住宿，也不是独立游客数 |
| `Dashboard.vue` KPI | 农产品销售额 | **近 7 日**农产品销售额 | 该值是 7 日窗口，与"今日"的客流混在一屏上 |
| `Dashboard.vue` KPI | 乡村到访占比 | **今日**乡村到访占比 | 同上，标明周期 |
| `Dashboard.vue` 趋势图 | 全市到访 | 核心景区到访 | 趋势的 `visitors` 只累加 SCENIC |
| `Dashboard.vue` 销售额图 | 体验驱动 | 按产地归集 | 合成数据只支持到**乡村点级**，不是单品排行 |
| `Dashboard.vue` 面板 | **AI** 运营建议 / 规则 + **LLM** | 运营建议 / 规则引擎判定 | 文案是写死的模板，**没有一步经过模型** |
| `PoiDetail.vue` | **实时**承载 | **当日**承载 | 数据是日粒度（一个资源点一天一行），不是实时流 |
| `Itinerary.vue` / `Explore.vue` / `Home.vue` | 实时承载/余量/占用率（6 处） | 当日承载/余量/占用率 | 同上 |

> **为什么"AI 运营建议"必须改**：经不起追问。评审问一句"这段是哪个模型生成的"
> 就答不上来。而且改掉之后反而**更强**——本项目的第三个创新点正是
> "规则引擎 + 多智能体双向决策中枢"，规则引擎判、模型只负责解释，这才是要讲的。
> M7 的 `POST /api/ai/analyze/ops` 上线后，把标题改回去、并让文案来自接口。
>
> **2026-09-27 补记（M7 已落地）**：标题已改为「AI 运营解读」，文案来自接口，
> 写死的模板已删除。端点的实际路径是 `POST /api/admin/ops/analyze`
> （不是这里写的 `/api/ai/analyze/ops`，原因见 M7 验收记录「三、第 1 条」）。

### 6. 「生成分流工单」按钮从死按钮变成真按钮

Dashboard 上原本有这个按钮，但**没有绑定任何事件**（点了没反应）——
违反本项目"分阶段开发不要放做不了的按钮"的约定。

本轮接上：对快照里**第一条 `OPEN`** 的风险建单（不是"全市最严重的"，
快照只有 5 条且已按"等级优先 + 类型多样"挑过），建完刷新快照并弹提示。
全都处置过时按钮**置灰并改文案**而不是隐藏——隐藏会让人以为这一页没有这个能力。

### 7. 分流候选：规则引擎不解析，但候选**不在前端**了（第二轮上移回后端）

`docs/模块划分与依赖.md` 的 M1 预留点表原写"规则引擎读 `poi_relation` 的 `DIVERSION` 边
作为分流候选，再叠加真实承载过滤"。**规则引擎没有这么做，而且不该这么做**：

| | 设计稿 | 实现 |
|---|---|---|
| 谁判定"这一带有压力" | 规则引擎读边 | 规则引擎按 **`poi.district`** 聚合（`RuleEngine.evalRuralIdle`）—— **两轮都没变** |
| 谁给具体候选点 | 规则引擎读边 | **后端 `DiversionAdvisor`**（`service/support/`，纯函数）：读 `DIVERSION` 边 + 当日承载，出有序候选与理由文案 |
| 谁消费候选 | —— | ① 运营端风险卡上的"分流方案" ② 公告草稿的候选快照与正文 ③ 详情页自动兜底块（前端仍读 `/api/pois/{id}` 的 `diversion`，阈值与 Advisor 同取 75%） |

理由：`poi_relation` 是 M1 的数据（导入时按距离重建），表达的是"**空间上**可以承接"；
"**当前**能不能承接"是 M5 的承载数据。把两者在**规则引擎里**合并，等于让 M5 去读 M1 的表 ——
M5 会多一个对 M1 表结构的硬依赖（换城市、改边规则都要动 M5）。规则引擎因此保持
"只读 `poi` + `poi_visit_stats`"的干净输入；`DiversionAdvisor` 是**独立一步**，不在规则引擎的输入里。

**★ 第一轮写成"前端做"，第二轮（分流公告）又上移回后端，这是有意的**：

- 第一轮只有一个消费方 —— 详情页给个建议。前端算只多一次**本来就已经在发**的请求，很划算。
- 第二轮的消费方是**要落库的公告**。落库内容必须**服务端可复现**：答辩问"这条公告为什么推
  这个村"，答案得是数据，不能是"浏览器算的"。同一份草稿换台机器打开必须是同一批候选。
- 上移的代价是"详情页与 Advisor 两处口径"，靠**同一个阈值常量 75%** + 探针对照组（验收记录
  第 5 节 44/46–49 条）来锁住，而不是靠人记得。

`DiversionAdvisor` 写成**纯函数**（无 Spring 依赖、无 IO）是为了能**离线验排序**：现存数据里
"承载过半后置"这一档**永远不会被触发**（50–75% 的点都被更近更空的挤掉了），只能在内存里
喂人造数据直接看输出。离线校验脚本 `.workbuddy-ai/tmp/AdvisorCheck.java`，**17/17 PASS**。
参数（半径 90 km、承载上限 75%、过半后置线 50%）**是代码常量、不进数据库** —— 它们决定的是
**推荐顺序**而不是"报不报警"，运营没有日常调它们的场景，且必须**跨环境可复现**。

### 9. 参赛方案回核：实现与设计稿的**七处**口径收敛

`docs/汉游智脑V2.0-参赛落地方案.md` 是评审要看的文档，它写的是**设计口径**。

| 方案原文 | 实现 | 为什么必须标记 |
|---|---|---|

| §15 链路 ②「游客端：AI 行程规划时 `rural_agent` 权重上调，生成乡村替代方案」 | **未实现**：公告是**独立展示**，不会改写已生成的行程；`plan_itinerary` 也没有"因承载高而调权重"这个输入 | 真要做需要把当日承载接进 M4 的排序输入，那会让**同一句话问两次得到不同行程** —— 演示时不可解释。当前做法是**把候选点摆出来、点进详情页**，决定权留在游客手里 |
| §16 `poi_visit_stats` 的 `hour` 列 | 未实现，只有日粒度 | 方案的表结构比实现多一列 |

> **处理方式是"在方案里标差异"，不是"改实现去迎合方案"。**

## 八、第二轮：分流公告（同日续做）

### 1. 为什么这一轮非做不可

第一轮结束时，M5 的能力链是"**判得出**（风险事件）→ **派得下**（工单）→ **看得见**（承载显示）"，
但**没有任何一步到游客端**。规则算出"兴汉胜境该分流到哪三个村"，只有运营看得见；
游客仍然照原计划去挤。这一轮补的就是这一段：**把规则算出的候选写成人话，经人工发布后
出现在游客端**。它是三个创新点里"客流'下乡'引导"的**唯一可见证据**。

### 2. 五个设计决定（都不是"顺手"）

**① 候选上移回后端，且做成纯函数。** 理由与代价见「四、第 7 条」。一句话：**要落库的东西
不能由前端算**，否则同一条公告换台机器打开内容不同。

**② 公告必须人工发布，不做自动下发。** 承载率来自**仿真数据**。让系统自动对游客喊话，
出错时没人拦得住；而运营点一下"发布"的成本极低。所以草稿 → 发布是**两个动作**，
中间可以改文案。这也是 §15 链路①"一键下发推荐位"收敛为"生成草稿"的原因。

**③ 候选以「快照」落库，发布后不再随承载变化。** `candidates_json` 存的是**生成那一刻**的
承载（界面上写"推荐时 28%"）。不这么做的话，昨天发的公告今天再看会显示今天的承载 ——
运营无法解释自己发过什么。**公告是那一刻的决定，不是一个实时视图。**

**④ 过期语义在查询侧，不靠"标记动作"。** 游客端接口的过滤条件是
`status=PUBLISHED AND expire_at > now()`。另有一个 `expireOverdue()` 把到期的行标成
`EXPIRED`，但**它只影响运营端列表的显示**（启动时 + 运营端列表接口返回前各跑一次），
**不决定"能不能发布"** —— 那个判定直接比 `expire_at`。若反过来靠 `status`，
"公告有没有过期"就取决于标记动作有没有跑过，同一个操作的结果取决于环境，
是最难查的一类 bug（这是这一轮修掉的第二个真问题，见下）。

**⑤ 详情页：公告 banner 与自动兜底块互斥。** 同一个点上同时出现"官方公告推荐这 3 个村"
和"系统建议去这 3 个村"（可能还不是同一批），是两套说法。有公告时兜底块让位。

### 3. 这一轮修掉的两个真问题（都是"操作路径被堵死"）

| 问题 | 症状 | 修法 |
|---|---|---|
| **过期公告是死路** | `createDraft` 的重复判定是"该事件下**有任何**公告就拒"（8011），而 8015 又拒了"重新发布已过期公告"。公告一旦过期，运营**既不能重发、也不能重新生成**，只能去数据库删行 —— 而 8015 的提示语写的偏偏是"请重新生成" | `createDraft` 改成：已存在**未过期**公告才报 8011；**已过期时放行**，复用同一行（id 不变，`uk_event` 不被破坏）重算候选、换发新编码、回到草稿。8015 那句话这才真的走得通 |
| **8015 的判定看 `status` 而不是"是否真的过期"** | 守卫写的是 `status == EXPIRED`，而 `status` 由 `expireOverdue()` 置。于是同一个操作，**结果取决于那个标记动作有没有跑过** | 改成直接比 `expire_at` 与当前时间。`expireOverdue()` 只负责让运营端列表**好看**（把过期的标出来），不再决定能不能发布 |

> 两个问题都是**接口验收脚本**（`accept_m5_diversion.py`）跑出来的，不是读代码看出来的 ——
> 第 11 组"过期后重新生成"这条断言，是第一版脚本里**没有**的，是查 8015 为什么红时才补上的。

### 4. 一处后端与前端的口径必须对齐

`DiversionAdvisor.USAGE_BAR = 0.75` 与 `PoiDetail.vue` 里自动兜底块的过滤阈值是**同一个数**。
两处不一致就会出现"**公告推荐了详情页不推荐的村子**"—— 游客点进去发现那个村子在详情页上
被标成"承载偏高"。这个约束靠三样东西锁住：源码注释互相点名、验收探针第 46–50 条的对照组、
以及本文件这一节。**没有靠"记得改两处"。**

### 6. 一个花了时间的坑（记在这里，别重踩）

`Risks.vue` 新增的「分流公告」标签页写成 `<template v-else-if="tab === 'notices'">`，
而它前面是工单那一支的 `<template v-else>`。**`v-else` 必须是最后一只**，
所以整个 SFC 编译失败 —— Vite 对该模块返回 **500**。后果不是"某个标签页坏了"，而是
**这个路由的组件永远加载不出来**：点侧栏「风险与工单」时 Vue Router 的导航被中止，
`location.pathname` 停在原处，看上去像"**点击没反应**"。

两件事值得记住：
1. **`vue-tsc --noEmit` 查不出这个**（模板编译错误不是类型错误），所以"类型过了"不等于"能跑"。
2. 排查只需要一条命令 —— 问 dev server 要那个模块，看是不是 500：
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:5173/src/views/admin/Risks.vue"
   ```
   已写进技能 `cdp-layout-probe`（"A route that won't navigate is usually a compile error"）。

修法是给工单那一支显式条件（`v-else` → `v-else-if="tab === 'orders'"`），
而不是把新标签页挪位置 —— **三支都用显式条件，谁先谁后都不影响渲染。**
