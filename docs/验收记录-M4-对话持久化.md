## 一、问题

`turns` 原本是 `Agent.vue` 里的一个**组件级 `ref([])`**。组件一卸载，它跟着没了：

| 用户动作 | 结果 |
|---|---|
| 切到「探索汉中」看看景点，再切回来 | 整段对话清空 |
| 顺手按一下 F5 | 整段对话清空 |

刚问出来的酒店列表、刚排好的两日游行程，一切走就没了，只能重问一遍。
这不是"少个功能"，是**助手看起来不可用** —— 用户不敢离开这一页。

## 二、设计

### 2.1 为什么是 `sessionStorage`，不是 `localStorage`

三条理由，按重要性排序（原文写在 `utils/agentChat.ts` 的模块注释里，这里给摘要）：

1. **它是"这一次访问的对话"，不是长期资产。** 用户的原话要求是"页面切换、组件重新
   挂载或页面刷新后还在" —— 这三件事 `sessionStorage` 全都满足。他**没有**要求
   "关掉浏览器明天打开还在"。
2. **`localStorage` 会把上一个人的对话留给下一个人。** 这台机器明天换个人用
   （演示现场很常见），打开助手页看到的是别人查过的酒店、别人选过的住处。
   `sessionStorage` 是**按标签页**隔离的，关掉标签页就结束 —— 与「清空对话」
   按钮的语义一致。
3. **会话令牌才需要跨浏览器会话。** 登录状态存 `localStorage` 是因为
   "关掉浏览器再打开还登录着"是明确需求（见 `stores/session.ts`）；
   对话历史没有这条需求，跟着令牌一起长期留存只是顺手，不是理由。

**代价：关掉标签页/浏览器，对话就没了。** 这是有意的，不是缺陷。

### 2.2 三条必须做对的边界

| # | 边界 | 不做的后果 |
|---|---|---|
| ① | **绝不把 `streaming: true` 存下来** | 用户在流式回答生成到一半时切走，回来那一轮**永远转圈**（没有流在推了），而 `streaming` 守卫还会让新提问**发不出去** —— 页面看着活着，实际卡死 |
| ② | **带版本号**（`VERSION = 1`） | `AgentTurn` 的形状会随功能演进（比如阶段五-a 刚加了 `itinerary`）。旧数据在新代码里渲染，表现是"某一块空白"或整页报错，而用户只会说"这个页面坏了"。版本对不上就**丢弃**，重新开始 |
| ③ | **有容量上限** | 卡片里带图片地址、来源里带摘要，一轮对话几百字节到十几 KB。`sessionStorage` 通常只有 5MB，写超了抛 `QuotaExceededError` —— 不管的话用户会看到"发一条消息就报错" |

- ① 的做法：写入时统一归一成 `false`，并给未生成完的那一轮补一句
  `'这次回答还没生成完就离开了页面'`（用户看到半截回答时得知道"这是没生成完"，
  而不是以为助手就答了这么点）。
- ③ 的做法：**轮数**（`MAX_TURNS = 30`）与**总字符数**（`MAX_CHARS = 400_000`）
  两个上限。超字符数时**每次砍掉最旧的 1/4**而不是一轮一轮砍 ——
  一次 `stringify` 就能少一大截，省掉几十次无谓的序列化。`setItem` 失败时
  再降一级（砍一半）重试，还不行就静默放弃：**这一次对话照常，只是刷新后看不到历史**。

### 2.3 落盘时机是**有限的四处**，不是 `watch` 全量

```
finish()            → 每轮对话结束时
onBeforeUnmount     → 组件卸载（内部调 stop() → finish()）
pagehide            → 整页刷新 / 关标签页
clearAll()          → 清空对话
```

**刻意不写成 `watch(turns, save, { deep: true })`**：流式回答每来一个 token 都会改
`turn.answer`，全量监听等于"每吐一个字就把整段历史序列化一遍"，几十轮之后会明显卡。

**`onBeforeUnmount` 在整页刷新时不会触发** —— 浏览器直接把页面丢掉，Vue 没有机会跑
卸载钩子。少了 `pagehide` 这一条，"回答还在生成时按 F5"就会丢掉那一轮
（而它恰恰是用户最想找回来的：他想看看刚才答到哪了）。

### 2.4 `id` 重排：避免 `:key` 撞号

读回来的 `id` **重新按顺序排 `1..N`**，而不是用存下来的值。理由：`id` 唯一的用途是
模板里的 `:key`，重复的 key 会让 Vue 复用错节点（表现为"回答串到了别的问题下面"）。
存下来的 id 可能是旧版本生成的、可能被人在开发者工具里改过，**重排一遍是唯一能保证
唯一性的做法** —— 而组件里 `seq` 只需取 `turns.length` 就能接着往下发号，不会与历史撞号。

### 2.5 清空与落盘的**顺序陷阱**

```ts
function clearAll() {
  if (streaming.value) stop()   // ← 这句内部会 finish()，也就是**落一次盘**
  turns.value = []
  clearAgentTurns()             // ← 所以必须**显式**再清一次存储
}
```

顺序写反（先清存储、再 `stop()`）的结果是"清空对话 → 刷新 → 旧对话又回来了"。
探针第 6 阶段专门验这一条。

### 2.6 读回来的数据要**逐字段兜底**，不能 `as AgentTurn`

存储里的数据可能来自上一个版本的代码，也可能被人在开发者工具里改过。
`reviveTurn()` 逐字段检查，**认不出来的一轮返回 `null`**（由调用方过滤），
而不是补一堆默认值 —— 一轮连问题都没有的对话，补出来也只是个空壳。
缺一个字段就让整页崩掉，代价远大于"这一格是空的"。

**任何异常都返回空数组**（`loadAgentTurns` / `saveAgentTurns` / `clearAgentTurns`
三个函数都包了 `try/catch`）：读不到只是"没有历史"，存不下最多是"刷新后看不到历史"，
都不该让助手页打不开或让这一次对话受影响。

### 2.7 挂载时**硬跳到底**

```ts
onMounted(() => {
  window.addEventListener('pagehide', onPageHide)
  void nextTick(() => {
    const el = thread.value
    if (el) el.scrollTop = el.scrollHeight     // ← 硬跳，不是 scrollTail()
  })
})
```

用户切回来想看的是**最新那一轮**。这里不能用 `scrollTail()` —— 那个函数有
"只在已贴底时才滚"的守卫（避免打断用户往上翻历史），而刚挂载时 `scrollTop` 是 0，
守卫会拦住它，用户看到的是最老的一轮。

## 五、已知边界（答辩要能说清）

1. **关掉标签页/浏览器，对话就没了。** 这是 `sessionStorage` 的语义，**有意的**：
   它是"这一次访问的对话"。要"明天打开还在"，得换 `localStorage` 并按账号隔离
   （见下条），而那不是用户提的需求。
2. **同一标签页内换账号登录，仍会看到上一个人的对话。** 对话按**标签页**存，
   不区分账号。用「清空对话」可以清掉。要做成按账号隔离，得在登录/退出时同步清理 ——
   注意**退出登录会先跳走再卸载组件**，组件卸载时的保存会把刚清掉的数据又写回去，
   所以不能只在 store 里清。
3. **恢复的历史里没有"时间"字段。** 界面上不显示"这是 10 分钟前问的" ——
   `AgentTurn` 里本来就没有时间戳，这一版也没加（加了就得处理"刷新后时间还对不对"）。
4. **被裁剪的历史是静默的。** 超过 30 轮或 400KB 时砍掉最旧的，界面上不提示
   "更早的对话已被清理"。当前演示规模碰不到这条。
5. **流式中途离开的那一轮，回来会带一句"这次回答还没生成完就离开了页面"。**
   这是**故意**补的说明，不是 bug —— 它比"给一段半截回答却不说"更诚实。

## 六、本轮未做

- 按账号隔离对话（退出登录时清理）。
- 对话的跨会话留存（`localStorage` / 服务端存历史）—— 未提出需求，且涉及
  "历史对话算不算个人数据"这个问题，不擅自做。
- 历史轮次的折叠 / 搜索 / 导出。
- 「我的行程」页（`Itinerary.vue`）的持久化 —— 它读的是服务端 `trip_context`，
  与对话历史是两回事，本轮未动。
