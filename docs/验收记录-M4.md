## 一、模块职责边界

**做**：让 AI 先判断用户这一问该走哪条数据源（本地知识库 / 高德地图 / 直接回答），
再**真的去查**，最后把查到的真实数据组织成一段推荐。第一阶段落地三个工具：
`knowledge_search`（复用 M3 检索）、`search_nearby`（高德周边搜索）、
`search_poi`（高德关键词搜索）；返回酒店/餐厅/景点卡片给前端渲染。

**不做（第一阶段明确不做，不是漏做）**：

- **不做酒店预订**：没有库存、没有支付、没有订单、不接美团/携程内部接口。
  卡片下方明写「本页只做推荐，不提供预订」。
- **不做「选择酒店」**：那需要 TripContext 持久化（阶段二）。**也刻意不放这个按钮** ——
  放一个点了不做事的按钮，比没有按钮更糟。
- **不做「去预订」跳转**：阶段五。第一阶段的卡片上没有任何预订入口。
- **不做路线规划**（`get_route`，阶段三）、**不做网站自有商品检索**
  （`website_food_search`，阶段四）、**不做行程规划/多天/天气**（阶段五）。
- **不建任何数据库表**。第一阶段不写库，`citypack/` 也没改。

**三条设计红线没有被触碰**：

1. **核心不是电商。** 这一页没有任何加购/下单入口；推荐与预订被明确分开。
2. **核心不是聊天机器人。** 页面的重点不是对话框，而是**工具调度过程**：
   顶部能力徽标、每条回答上方的工具状态条（`running → done`、返回条数、耗时），
   把"它真的去查了"显式摆出来。页面上不打「基于 Multi-Agent」这类标签。
3. **不编造真实旅游数据。** 酒店名、地址、经纬度、距离、电话全部来自高德返回，
   **不经过模型转述**（见 7.2）。模型只负责理解需求、决定调什么工具、综合结果、
   用自然语言推荐。提示词里把"不许编造评分/步行时间/房型价格"写成硬规则。

## 三、接口定义

### `POST /api/ai/agent`（Java）→ `POST /ai/agent`（Python）

请求体与 `/api/ai/qa` 一致：`{"question": "..."}`。响应是 SSE，事件顺序：

```
meta → tool(running) → tool(done|error) → cards(可选) → delta × N → done
```

任一步出错发 `error` 并结束。各事件字段：

| 事件 | 字段 |
|---|---|
| `meta` | `mode`（llm/extractive）、`generator`、`city`、`amap`（高德是否已配）、`tools`（本次可用工具名） |
| `tool` | `name`、`status`（running/done/error）、`label`、`count`、`elapsed_ms`、`error` |
| `cards` | `kind`（**判别式**：`knowledge` 为来源卡片，其余为高德 POI）、`items` |
| `delta` | `text` |
| `done` | `mode`、`tool`（本次实际用的工具）、`elapsed_ms` |

**为什么不并进 `/ai/qa`**：`/ai/qa` 的 `meta` 描述的是"检索行为"（`route`/`mode`/`sources`），
Agent 的 `meta` 描述的是"用了哪个工具"（`tools`/`amap`），`done` 里还多一个 `tool`。
两套语义塞进同一端点，前端每处都要判断"这次有没有 tool 字段"，
而 M3 已验收的契约也会被改动。多一个端点的代价，远小于污染一个已验收的协议。

**权限**：`/api/ai/**` 在 `SecurityConfig` 里整段 `permitAll`（问答能力对未登录游客开放，
与 M3 一致），所以新增端点**不需要再配一次**。这一点写进了 `AiController` 的类注释 ——
免得后来人以为漏配。反过来说，这一层**不能放需要登录才能做的动作**。

## 四、高德 key 填在哪里

写根目录 `.env`（`.env.example` 已补上说明）：

```
AMAP_KEY=            # 高德开放平台的【Web 服务】key
AMAP_BASE_URL=       # 留空用默认 https://restapi.amap.com/v3
AMAP_TIMEOUT_S=8
```

- **必须是「Web 服务」类型的 key。** 拿「Web端(JS API)」或「Android/iOS」的 key 调 REST 接口，
  返回 `status=0 + infocode=10009`，而那一行日志看起来很像"这个地址查不到"，极易查错方向。
- **key 不出后端**：Java 与前端都不持有它，只有 Python 读 `.env`。
- **留空 = 降级**，不是报错：工具清单里去掉高德那两个，页面显示「高德未配置」，
  且**不再给出任何"附近…"的示例问题**（点了必然失败）。

## 六、本轮修复的缺陷

### 6.1 ★ `knowledge_search` 的卡片会被前端当酒店卡渲染（浏览器验收发现）

`tools.py` 里知识库分支也下发 `cards`，但那是 M3 的**来源**结构
（`title/source_name/source_url/source_kind/snippet`），字段与高德 POI 卡片几乎不重叠。
前端若统一按地点卡片渲染，结果是**整片空白卡**（没有 `name`、没有 `photo`）。

修法：`cards` 事件的 `kind` 作为**判别式**，类型上拆成两个联合分支
（`kind: 'knowledge'` → `AgentSourceCard[]`，其余 → `AgentCard[]`），
`AgentTurn` 也把 `cards` / `sources` 分开存。前端按 `kind` 分支渲染，
来源卡片复用与知识问答页同一份 `QA_DOC_TYPE_LABEL` / `QA_SOURCE_KIND_LABEL`。

**这个缺陷离线自检抓不到**（后端两侧都自洽），只能靠浏览器验收。所以 5.5 的 D 组
专门留了 `D2 知识库分支没有误渲染成地点卡片` 这条断言。

### 6.2 ★ 提示词让模型描述了一个界面上不存在的按钮

`SYSTEM_PROMPT_TOOLS` 原第 7 条写「用户要订房时，告诉他可以在**卡片上跳转**到第三方平台自行预订」。
但第一阶段的卡片上根本没有这个按钮。实测模型照着说了：

> 「确定目标后，可以在卡片上跳转到第三方平台自行预订。」

用户会去找一个不存在的东西。修法：把该条改成**只陈述边界、不承诺 UI**：
「不要描述界面上有『预订』按钮或跳转链接 —— 这一版没有这些按钮」。
复测后回答变成「我无法提供，也不代订……请自行到第三方平台或直接致电查询、预订」。

**教训**：提示词里写"界面上有什么"，等于让模型替前端做产品承诺。以后这类内容
要么不写，要么与真实 UI 同步维护。

### 6.3 搜索中心只给了坐标、没给名称，模型只能靠地址反推

实测「汉中高铁站」被地理编码到 **「陕西省汉中市洋县高铁站(公交站)」**（约 107.5257, 33.2268），
而用户多半指的是汉台区的汉中站。给模型的工具文本里原本只有 `搜索中心：107.525665,33.226810`，
模型是**从一批"洋县"地址里反推出**中心在哪儿的 —— 反推对了是运气。

修法：把地理编码解析出的**标准名称**一并写进给模型的文本（`搜索中心：<名称>（<坐标>，半径 N 米）`），
并加一条提示词规则：中心被替换过时必须开头如实说明。复测后模型开篇即说：

> 「您问的是『汉中高铁站』附近，但本次查询实际定位到的搜索中心是**洋县高铁站（公交站）**……如果您要的是汉中站（汉台区），这批结果不适用。」

**已知限制（未修）**：「汉中高铁站」不是标准地名，而洋县确实有高铁站，所以地理编码
选中洋县并不算错，但很可能不是用户想要的。可行的后续做法是**让用户从候选中心点里选一个**
（`/v3/place/text` 可返回多个候选），那属于阶段二"选择"的范畴，本轮不做。

### 6.4 `search_poi` 名称完全没命中时不作声

实测查「汉中博物馆」返回的是拜将坛、古汉台 —— **没有一条名字里带"汉中博物馆"**。
不说明的话模型可能把第一条当成"就是它"。

修法：关键词未被任何一条名称命中时，在工具文本开头显式说明（并列出前 3 个实际返回的名称）；
命中时**不加**这句废话（避免每次搜索都挂一句无意义提示）。两条都有断言。

修完复测，模型的开篇从"自己察觉"变成"依据工具说明"：

> 「这次没有查到『汉中博物馆』这个地点本身，高德返回的是它认为相关的附近地点，
> **其中没有任何一条名称是『汉中博物馆』**，所以我不能指认哪一条就是它。」

区别在于：**前者是模型的判断力（可能失手），后者是工具给的事实（不会失手）**。

### 6.5 ★ 配置项留空被当成空串（`AMAP_BASE_URL=` 会让 base_url 变成 `""`）

`.env` 里写 `AMAP_BASE_URL=`（留空，意思是"用默认值"）时，
`os.environ.get("AMAP_BASE_URL", default)` 返回的是**空串**而不是 default —— 因为键存在。
后果：base_url 变成 `""`，请求打到 `/geocode/geo` 这种没有 host 的地址上，报错方向完全错。
数字型更糟：`AI_SERVER_PORT=` 会让 `int("")` 在 **import 期抛异常，整个服务起不来**。

修法：补 `_str` / `_int` / `_float` 三个 helper（与已有的 `_bool` / `_path` 同一套路），
**留空按没配处理**；非数字则退回默认值并在 stderr 喊一声，而不是崩。
全文件 13 个字段统一切过去（不只是新加的高德那三个 —— 只修一半会变成
"AMAP_BASE_URL 留空可以，AI_SERVER_PORT 留空会崩"，比都不修更难解释）。

### 6.6 其它

- `_search_nearby` 把「该范围内没有查到」标成了 `error`，前端会显示**红色失败态**，
  而实际发生的事是"查了，没有"。改为 `error` 只表示真故障（超时/key 无效/中心点定不下来），
  空结果由 `count=0` 表达。
- `agent.py` 模块注释写「解析失败就退回 `none`」，实际是退回 `knowledge_search`。
  已改正，并把两种失败（格式坏 / 工具名不认识）的区别写清楚。

## 七、关键设计验证

### 7.1 为什么用自写 JSON 路由，不用原生 `tool_calls`

1. **决策不需要流式。** 它是一次短输出（一行 JSON），而原生 `tool_calls` 在 `stream=true`
   时要按 `index` 累加增量再拼，各家实现细节不一致，拼错的表现是"参数偶发丢失"。
2. **可移植。** `.env` 允许换通义 / Kimi / 本地 Ollama，自定 JSON 协议只依赖
   "模型会输出 JSON"，不用为每个厂商重验 `tool_calls` 语义。
3. **可解释。** 决策原文进日志（`[Agent] 决策 tool=… args=… raw=…`）。
   答辩被问"它真的调工具了吗"，答案是那一行日志，而不是"应该调了吧"。

代价是自己解析模型输出，所以 `_parse_decision` 写得宽容（去围栏、取首个 `{` 到末个 `}`），
并用 9 条脏输出用例锁住行为。

### 7.2 `ToolResult` 为什么有两个输出（`text` + `cards`）

模型输出是**自然语言**，而卡片字段必须**逐字准确**（用户要照着 `tel` 打电话、
照着 `address` 导航）。让模型把结构化数据转述一遍、前端再解析回来，
中间任何一步出错都是"酒店名少个字"这类现场极难解释的问题。
所以：**给模型的走 `text`（允许只引用），给前端的走 `cards`（逐字来自高德）**。

浏览器验收里 `C5/C6/C7` 三条断言（名称、地址、距离）就是这条设计的回归保护。

### 7.3 为什么不缓存 Agent 的答案

M3 的 `AnswerCache` 在这里用不上：答案依赖**实时**高德数据。回放一份缓存酒店列表 =
用户照着打电话，那边说"我们早搬走了"。所以 Agent 的**离线路径**是**规则兜底**
（回退 `knowledge_search` + `extractive_answer`），不是"回放上次答案"。

### 7.4 中心点被替换时必须显式说明

这是"不要静默"原则在地图场景的具体落地：用户问的是 A 附近，答的是 B 附近，
**不说明就等于答错了问题**。实现上做了两件事：①`center_note` 写进给模型的文本；
②提示词里加一条"中心被替换过必须在开头说明"。6.3 的实测就是这条生效的证据。

### 7.5 工具失败一律降级，不中断整轮对话

高德超时 / key 无效 / 地址查不到，都降级成一条空结果 + 一句说明，由模型告诉用户
"这次没查到"。用户看到的是「附近没查到酒店」，而不是一个红色报错 ——
整轮对话不该因为一个外部服务抖动就中断。
