## 〇、先说三件必须先知道的事（数据现实）

在动手之前查库得到的结论，**直接决定方案能不能成立**。三条都是好消息，两条是硬约束。

### 0.1 ★ 餐饮 / 住宿的数据**本来就存在**，不需要新表

`poi.business_type` 实际分布（42 个点）：

| business_type | 点数 | 说明 |
|---|---|---|
| `SCENIC` | 18 | 核心景区 |
| `RURAL_SPOT` | 12 | 乡村景点 |
| `FOOD` | 6 | **餐饮** |
| `LODGING` | 4 | **住宿** |
| `TRANSPORT` | 2 | 高铁站 / 支线机场（驾驶舱口径**不含**） |

`poi_visit_stats` 是 **42 点 × 60 天 = 2520 行**，**覆盖全部业态**：

| 业态 | 统计行数 | 窗口总到访 |
|---|---|---|
| SCENIC | 1080 | 4,605,348 |
| TRANSPORT | 120 | 837,698 |
| RURAL_SPOT | 720 | 144,028 |
| LODGING | 240 | 42,096 |
| FOOD | 360 | 28,176 |

**结论**：餐饮管理 / 住宿管理两个新页面**零新增表、零新增数据**，直接用现有 `poi` + `poi_visit_stats`。

### 0.2 ★ 硬约束一：餐饮 6 个点、住宿 4 个点 → 做不出「Top10」

| 业态 | 点位数 | 点位清单 |
|---|---|---|
| 餐饮 | **6** | 汉中热面皮（老字号）/ 宁强麻辣鸡馆 / 略阳罐罐茶 / 洋县有机黑米膳坊 / 汉江鱼府 / 西乡牛肉干铺 |
| 住宿 | **4** | 天汉景逸酒店 / 华阳古镇民宿群 / 青木川古镇客栈 / 留坝楼房沟民宿 |

**方案**：图表标题写 **「餐饮热度排行（全部 6 家）」**、**「住宿热度排行（全部 4 家）」**，
**不写 Top10**。写 Top10 而只画出 6 根柱子，是答辩现场最容易被抓的"数字对不上"。

### 0.3 ★ 硬约束二：图片与评价数据很薄

| 数据 | 实际条数 | 覆盖 |
|---|---|---|
| `poi_image` | **5** | SCENIC 2 / RURAL_SPOT 2 / FOOD 1 / **LODGING 0** |
| `site_banner` | 4 | 轮播图 |
| `poi_comment` | **2** | **全部在 SCENIC**，餐饮/住宿/乡村 0 条 |
| `order_review` | 9 | 订单评价 |

**方案**：
- 缩略图**有就显示、没有就回落占位图**（复用 `getPoiCovers()` + `Resources.vue` 现有的"手写 SVG 回落"做法），
  **不为了好看造图片数据**（你在 §十三 明确禁止）。
- **餐饮「评价构成」这张图砍掉** —— 没有数据源。改为「**承载状态构成**」（有数据）。
- 景点/乡村的「评价」用现有 `poi_comment`（2 条），列表里显示"评价数"而不是"评分分布"。

## 一、最终管理员信息架构（7 个一级页面）

| # | 页面 | 路由 | 定位 | 来源 |
|---|---|---|---|---|
| 1 | **管理驾驶舱** | `/admin/dashboard` | 看全局 | 改造现有 `Dashboard.vue` |
| 2 | **农产品管理** | `/admin/products` | 农产品 + 订单 | 拆 `Resources.vue` 的 product 标签页 + 并入 `Orders.vue` |
| 3 | **乡村景点管理** | `/admin/attractions` | 核心景区 + 乡村景点 | 拆 `Resources.vue` 的 scenic 标签页 |
| 4 | **餐饮管理** | `/admin/restaurants` | 餐饮 | 拆 `Resources.vue` 的 food 标签页 |

| 7 | **图片管理** | `/admin/media` | 配图 / 轮播 | **保留 `Media.vue` 不动** |

**旧路由保留为跳转**（不破坏任何已有链接 / 书签 / 答辩截图）：

| 旧路由 | 新去向 |
|---|---|
| `/admin/resources?kind=scenic` | → `/admin/attractions` |
| `/admin/resources?kind=food` | → `/admin/restaurants` |
| `/admin/resources?kind=product` | → `/admin/products` |
| `/admin/resources?kind=comment` | → `/admin/attractions?tab=comment` |
| `/admin/orders` | → `/admin/products?tab=orders` |

> ★ **为什么保留跳转而不是删掉**：驾驶舱的 5 张 KPI 卡现在指向 `/admin/resources?kind=...`，
> 验收记录、答辩 PPT 截图、以及 `probe_dash_range.mjs` 的 27 条断言都写着这些 URL。
> 直接删路由会让**已验收的断言全部变红** —— 而那不是功能坏了，是我们自己拆的。
> 跳转层让"旧链接仍可用"，同时把断言的**期望值**更新到新路由（见 §七 实施步骤）。

## 二、页面统一骨架（7 个页面共用）

```
┌ 页面标题 + 统计区间（TODAY / LAST7 / LAST30 / ALL）
```

**管理操作一律走 Drawer / Modal，不做整页表单**（沿用 `Risks.vue` 已验收的抽屉范式）。

## 五、需要新增的接口（**只要 1 个**）

### `GET /api/admin/ops/business?type={scenic|rural|food|lodging|product}&range={...}`

**为什么必须新增**：现有接口没有"**按业态 × 统计区间**"的明细。
`/stats/pois` 是**公开端点**（游客端读拥挤度）且**只有今日 + 近 7 日、没有 range**；
`snapshot` 只给聚合值和 Top6。四个业务页面都需要 per-poi 排行 / 逐日趋势 / 区县分布。

**实现方式**：**复用 `OpsServiceImpl` 现有的 `loadContext` / `sumWindow` / `avgUsageByPoi`**，
与 `snapshot` 走**同一份取数逻辑**（不是第二套算法）。返回结构：

```jsonc
{
  "range": "LAST7", "range_from": "2026-09-28", "range_to": "2026-10-04",
  "period_label": "统计区间 2026-09-28 ～ 2026-10-04（7 天 · 仿真）",
  "kpis": { /* 按 type 不同：见下 */ },
  "top":    [{ "id": "P-FOOD-001", "name": "汉中热面皮（老字号）", "value": 8379, "sub": "汉台区" }],
  "trend":  [{ "date_iso": "2026-09-28", "label": "周一", "visitors": 1234, "purchases": 12, "repurchases": 3, "sales": 3210.0 }],
  "districts": [{ "name": "汉台区", "value": 12284 }],
  "scatter":   [{ "name": "石门栈道", "x": 41234, "y": 0.93, "district": "汉台区" }],   // 仅 scenic/rural
  "distribution": [{ "name": "正常", "value": 12 }]                                      // 承载档 / 分类
}
```

各 `type` 的 KPI：

| type | KPI |
|---|---|
| `scenic`（含 rural，或分开传） | 到访 / 平均承载率 / 高负荷数 / 风险数 |
| `food` | 资源数 / 客流 / 承载均值 / 高负荷数 |
| `lodging` | 资源数 / 客流 / 承载均值 / 高负荷数 |
| `product` | 销售额 / 购买笔数 / 乡村复购率 / 产地数 |

**这是"最小新增"**：1 个端点 + 1 个 VO，**5 个页面共用**。

### 另外两处**必须**的小改（不是新接口）

| 改动 | 文件 | 量级 |
|---|---|---|
| `type` 参数支持 `lodging` | `AdminResourceServiceImpl.businessTypesOf()` | **3 行**（加 `TYPE_LODGING` 常量 + 一个 `if` 分支） |
| `EChart.vue` 注册 `ScatterChart`（+ `GaugeChart`） | `web/src/components/EChart.vue` | **2 行 import + 2 行 use** |

> ★ 住宿管理**不加这个 `lodging` 分支就完全没法用**：现在传 `type=lodging` 会抛
> `RESOURCE_TYPE_INVALID`（"未知的资源类型"）。这是新页面的**前置条件**，不是可选项。
