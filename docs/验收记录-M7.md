# M7 运营分析与决策 · 验收记录

> 验收日期：2026-09-27 · 结论：**通过（后端 + 前端）**
> 模块范围：`server-ai/app/ops_analysis.py`（三段式解读 + 依据 + 离线缓存）→ `POST /ai/analyze/ops` → `AiClient.postJson` → `POST /api/admin/ops/analyze` → 驾驶舱「AI 运营解读」面板
> 模块目标（`docs/模块划分与依赖.md` 第 47 行）：**把"运营快照里的一堆数"变成运营人员能直接用的三段式解读，并让这段解读可核对、可离线演示、不越权**。
> 上游：M5 的运营快照（`GET /api/admin/ops/snapshot`）。M7 **不建表、不写库**，只读快照。

## 一、模块职责边界

**做**：
- 把**已经算好**的一组指标交给模型讲成三段式：发生了什么 / 为什么（**归因假设**）/ 建议做什么；
- 每个维度附一份**由代码算出的**「依据」，让这段解读可以对着面板核；
- 六个解读维度（总览 / 趋势 / 业态构成 / 冷热失衡 / 销售 / 风险），一次只解读一组；
- 离线可演示：`server-ai/cache/ops_demo.json` 由脚本跑真实调用生成，断网时回放，
  并**明确标出**"这是回放、数据是不是同一批"；
- 驾驶舱把写死的模板文案换成真实接口。

**不做**（每一条都有明确理由，见「四」）：
- **不做取数** —— 指标由 Java 侧算好传进来。Python 侧 `metrics` 为空直接 400；
- **不做判定** —— 判定仍由 M5 的规则引擎做，模型只解释。所以第二段叫「归因**假设**」；
- **不新建表** —— 读 M5 / M6，自身不产生业务数据；
- **不做写操作** —— 没有"采纳建议"这类按钮，建议转工单仍走 M5 的风险卡；
- **不做 NL2SQL**（方案 §14 的 P1）—— 见「八」的文档回核；
- **不回落成模板文案** —— 取不到就 `mode=unavailable` + 一句原因。

**两条红线没有被触碰**：
1. **不是聊天机器人** —— 这里是"点一下出一份解读"的**报表动作**，非流式、
   返回结构化结果（三段 + 依据 + 模式），与 M3/M4 的对话协议（SSE）是两套东西，
   刻意不合并；
2. **不是"AI 说啥就是啥"** —— 每一个数字都由 Java 算好、模型不许引入新数字；
   依据由代码算不由模型复述；模式（真调了模型 / 回放 / 不可用）**必须显示**。

## 四、关键设计验证

### 1. 路径：从 `/api/ai/analyze/ops` 改成 `/api/admin/ops/analyze`

方案与模块文档原来都写 `/api/ai/analyze/ops`。**落地时改了**，理由是安全边界：

- `/api/ai/**` 在 `SecurityConfig` 里是**整段 permitAll**（M3 起：问答能力对未登录游客开放）；
- 而这个接口返回的正文与「依据」里带着**销售额、复购率、待处置风险数** —— 是运营数据；
- 放进 permitAll 的前缀下，等于游客也能读到。挂在 `/api/admin/**` 下才会被
  `ADMIN_PREFIX` 统一收进 `OPERATOR`，与 `/ops/snapshot` 落在同一条边界上。

`OpsAdminController` 的类注释里早就写明了这条思路（"漏配权限的后果是'访问不了'，
而不是'游客也能看到运营数据'"），M7 是同一处理的第二次应用。
**Python 侧的端点仍叫 `/ai/analyze/ops`** —— 它只监听回环、另有内部令牌，
所以方案 §16 的内部接口表不用改路径。

验收：`accept_m7.py` A 段 —— 未登录 4001。

### 2. 指标由 Java 取，前端**不能**传

Python 侧的接口只负责解读、**不做取数**。让前端把指标传进来有两个问题：
①"面板上的数"与"AI 解读的数"可以不是同一份（前端算错了也没人发现）；
②这个端点会变成一个免费的通用文本生成入口。

所以 `OpsAdminController.analyzeOps` 自己调 `opsService.snapshot()`，
用 `objectMapper.convertValue` 转成 Map（全局 snake_case 自动对齐 Python 期望的键名）。

Python 侧的守卫是**两层**的：`metrics` 缺失或为空对象都返回 400。
收下空指标再返回一段"什么都分析不了"的正文，比直接报 400 更难查 ——
调用方会以为是模型不行，实际是自己没传数据。

验收：`accept_m7.py` C 段 —— 缺 metrics → 400、空对象 → 400、未知 focus → 400。

### 3. 「依据」由代码算，不由模型复述

`basis_of()` 用 Python 格式化指标，**不让模型复述数字**。理由是它必须可核对：
模型会顺手改写（把 84,529 写成"约 8.5 万"、把 3.2% 写成"3%"），
于是"依据"和面板上的数字对不上 —— 而这一段存在的唯一意义就是"你能对着面板核"。

除总览外，每个维度都**把自己那一段明细的头几行列出来**：只给一两个汇总数，
模型讲细节时就没有可核对的锚点。例如"冷热失衡"会列出
`南郑区 景区/乡村承载 102.0% / 17.0%`，"风险事件"会列出 `明细中 HIGH / MID 3 / 2 条`。

验收：`accept_m7.py` B3 段 —— 依据与快照数字逐项比对（6 条）。

### 4. ★ 本轮最大的发现：**提示词里的口径错误会 100% 变成输出里的假话**

第一版缓存生成出来，逐条读的时候发现模型说了两句**特别像真的**的假话：

| 模型说的 | 实际口径 | 根因 |
|---|---|---|
| "当日**全市客流** 84529 人次" | `total_visitors` 是**核心景区**到访人次（不含乡村/餐饮/住宿/交通，且是人次不是独立游客数） | `FOCUSES["overview"].hint` 里**我自己**写的是"全市客流与乡村占比" |
| "南郑区**景区客流**为 102、乡村旅游客流仅 17" | `imbalance[].scenic/rural` 是**承载占用率百分比**（102 表示 102%） | `hint` 里写的是"各区县核心景区**客流**与乡村旅游**客流**的落差" |

**数字一个没错，说法全错。** 模型没有读错指标，它是照着我们的措辞讲的 ——
提示词里的口径错误会**原样出现在输出里**，而且因为数字是真的，看起来特别可信。

这暴露的是同一个问题的两层：
- **提示词层**：`hint` 的措辞必须与指标的真实口径一致；
- **指标层**：字段名本身看不出单位与分母（`total_visitors` / `scenic`），
  模型一定会替它们补一个最顺口的说法。所以**必须显式给出「指标口径」表**
  （`METRIC_GLOSSARY`），不能指望它猜对。

`OpsSnapshotVO` 里为同一个问题写了整整两段注释（"不是全市到访"、"不是独立游客数"），
但那些注释在 Java 侧，模型看不到 —— 口径知识**没有跨过语言边界**。

**修法（三步，每一步都重跑缓存并逐条读）**：

1. 重写全部 `hint` 的措辞，并在提示词里加入 `METRIC_GLOSSARY`（16 个易错字段的口径）；
2. 第二轮发现两个**表述瑕疵**：正文里出现英文字段名（"未闭环的 open_risks 为 16 条"）、
   0–1 的比例没统一换算成百分比（`0.3113` vs 依据里的 `31.1%`）。
   补两条通用规则：**不念字段名**、**比例一律说成百分比**（且已 0–100 的百分比数值
   **不要再乘 100** —— 混用会让某个数字凭空差 100 倍且看不出来）；
3. 第三轮逐条复核：`全市` 0 处、字段名 0 处、残留小数比例 0 处。

验收：`accept_m7.py` B2 段两条 + 全部 6 个维度的缓存逐条人工读过。

> **这条经验是通用的**：凡是"把结构化数据交给模型讲成人话"的功能，
> 口径说明是**输入的一部分**，不是文档。漏了它，输出的错误会以"听起来很对"的形式出现。

### 5. 「归因假设」的措辞：第二段叫 why 但正文必须写成假设

`SECTION_TITLES["why"] = "为什么（归因假设）"`，提示词明令"写成**假设**口吻
（例如'可能与…有关'），不要写成结论"。理由是**本系统没有做因果推断**，
把相关当因果是最容易被评审问倒的一句话。

实测 6 个维度全部遵守（例如"可能与…有关，但以上均为假设，尚不能判定因果"）。

### 6. 三级降级：`llm` → `cache` → `unavailable`，**不回落成模板**

| 情形 | `mode` | 界面 |
|---|---|---|
| 模型可用 | `llm` | 页脚署真实模型名 + 生成时间 |
| 离线 / 模型失败 / `DEMO_MODE=true` | `cache` | 徽标「离线回放」+ `note` 说明；数据换了则 `stale=true` 并说明"回放的是 X 那批" |
| 既没模型也没缓存 | `unavailable` | 徽标「暂不可用」+ `note` 说明原因，**三段为空** |

**`unavailable` 时不回落成模板文案** —— 驾驶舱原来那段"运营建议"就是模板，
M7 把它换掉的全部意义在于"这一段真的有模型参与"。再回落成模板，
界面会在不知情的情况下把模板当 AI 解读展示，那正是要消除的东西。

`stale` 的设计同理：**宁可口径说清楚，也不要让一段过期数字冒充当前解读**。

缓存**不能像 M3 的 `qa_demo.json` 那样手写**：M3 的答案是"知识库原文摘要"，
语料不变它就不变；而这里的解读**全是数字**，手写的第二天就和面板对不上。
所以由 `scripts/build_ops_demo.py` 跑一次真实调用生成，并记下每个维度的
`metrics_digest`（只覆盖**该维度用到的切片** —— 对整份快照算摘要，
任何一处数字变动都会让 6 个维度全部标成 stale）。

验收：`accept_m7.py` D 段 10 条 —— 回放三段齐、同批数据不标 stale、
换数据标 stale 且 note 说明、缺维度 → `unavailable` 且 sections 为空。

### 7. 「AI」这个标签的审计：M5 说不能标，M7 标了 —— 理由必须写清

M5 的验收记录里有一条口径审计：驾驶舱那块**刻意不叫「AI 运营建议」**，
因为从取数到成文全程确定，标成 AI 经不起追问。M7 上线后标题改成
「**AI 运营解读**」——这不是"改回来了"，而是**条件变了**：现在真的有模型参与。

三件事一起做了，缺一条就变成过度声称：
- 标题写「解读」而不是「建议」：模型解释的是**已经算好**的数，判定仍由规则引擎做；
- 面板内显示**模式徽标**（模型生成 / 离线回放 / 暂不可用）+ 页脚署真实模型名；
- 进页面**不自动跑**（避免"打开一次烧一次 token"，也让"点一下"成为明确意图）。

**回归探针的 D1 断言因此反转**：原来是"驾驶舱标题不含 AI / LLM"，
现在是"**只允许「AI 运营解读」一个**标题带 AI，其余仍不许"。
直接删掉旧断言是不行的 —— 那等于放弃这条审计，以后有人给模板块随手加个
"AI 建议"标题就没人拦了。

### 8. `AiClient` 的 `Accept` 头从写死改成参数

原来 `baseRequest()` 硬编码 `Accept: text/event-stream`，对三个流式端点是对的。
M7 的非流式端点也复用它 —— 一个 JSON 端点声称自己只接受 SSE，
在有内容协商的代理后面可能被改写成"缓冲到结束再返回"。

改成 `baseRequest(path, accept)`，三个调用方各传各的。顺带修好了 `getJson()`
（health / suggestions）的同一个问题。

### 9. 三个**我自己写错**的断言（记在这里，因为都很像"代码坏了"）

| 现象 | 真因 |
|---|---|
| `10) 三段的 kind 判别式正确` 红 | 断言用 `className.replace('ai__sec','')` 取后缀 —— `replace` 只替换**第一处**，class 是 `"ai__sec ai__sec--fact"`，取到的是 `ai__sec--fact` 而不是 `fact`。改用正则 |
| 探针 `SyntaxError: Invalid left-hand side expression in postfix operation` | 我在拼给 CDP 的**模板字符串**里写了注释，注释里带了反引号（`` `--` ``）→ 提前终止字符串，剩下的被当成运算符。**这是项目记忆里已经记过的坑，我又踩了一次** |
| `risks 依据至少 3 项` 红（`got=2`） | 这一条**是代码该改**：风险维度的依据只有 2 项（未闭环总数 + 明细条数），而模型正文里讲了"HIGH 级 3 条、MID 级 2 条" —— 依据里没有对应的数就没法核。补了分等级 / 分状态的明细行 |

前两条是断言错、代码好；第三条反过来。**分清楚这两类**是这一步的全部意义。
