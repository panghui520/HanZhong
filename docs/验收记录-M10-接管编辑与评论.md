## 一、这一轮解决的两个问题

### 1. 运营改不了数据包景点（"只能删或新增"）

M10 上线后，运营在景点列表里发现 `PACK` 行的**编辑按钮是禁用的**。当时的理由是对的（改了下一次启动就被数据包冲掉），但结果是**景点基本没法维护** —— 42 条景点里绝大多数来自数据包，能编辑的只有运营自己新建的几条。

**做法：不解除锁，而是"接管"。** 首次编辑一条 `PACK` 行时，把它的 `source` 从 `PACK` 改成 `ADMIN`；`CityPackImporter` 从此不再碰它。三点约束都守住了：

- **保留原 ID**（`P-SCE-001` 还是 `P-SCE-001`）—— 订单溯源、足迹、配图、关系全部按 id 引用，换 id 等于把这些引用打断；
- **不创建重复景点** —— 接管是 `UPDATE` 同一行，不是"复制一份 ADMIN 版"；
- **未接管的行完全维持原样** —— 导入机制只多了一个 `NOT IN (已接管 id)` 的过滤。

### 2. 景点评论是写死的

游客端"来过的人怎么说"用的是 `web/src/mock/reviews.ts` 的 `reviewsOf(poiId, businessType)` —— **按资源 id 派生的伪随机评价**。不同景点确实显示不同内容，但那是算出来的，不是任何人写的；口碑评分同理（`mock/stats.ts` 的 `ratingOf`）。

**做法：删掉 mock，换成 `poi_comment` 真表。** 整个 `web/src/mock/` 目录已删除。

## 四、PACK → ADMIN 接管机制（这是本轮最需要讲清的一件事）

### 4.1 触发点

`AdminResourceServiceImpl.updatePoi`：

```java
boolean takenOver = !SOURCE_ADMIN.equals(p.getSource());
if (takenOver) { p.setSource(SOURCE_ADMIN); }
```

- 接管**只做一件事**：把 `source` 从 `PACK` 改成 `ADMIN`。其余字段照常更新。
- `id` 全程不动。
- **单向不可逆**：没有"还原为数据包版本"的入口（见「九、已知缺口」第 1 条）。

### 4.2 导入器这一侧（少了这一步就是"改了某个景点之后后端再也起不来"）

`CityPackImporter.run()`：

```java
Set<String> takenOverPoiIds = takenOverPoiIds(cityCode);
...
pois.stream()
        .filter(p -> !takenOverPoiIds.contains(p.getId()))
        .forEach(poiMapper::insert);
```

`takenOverPoiIds` = `SELECT id FROM poi WHERE city_code = ? AND source = 'ADMIN'`。

**为什么必须跳过**：导入器按 `city_code` 删除重灌，删除条件已收窄为 `city_code = ? AND source = 'PACK'`，所以已接管的行**不会被删**；如果插入时不跳过，同一主键 `P-SCE-001` 会撞 `Duplicate entry`，而这一步在启动事务里 —— **整个启动回滚**，表现为"改了某个景点之后后端再也起不来"。

### 4.3 前端这一侧

`Resources.vue` 的编辑按钮**不再因 `source === 'PACK'` 而禁用**；`openEdit` 里先弹一次 `window.confirm`，把三件事说清楚（会保存到数据库且重启不覆盖 / 此后数据包不再同步这条 / 资源编码不变、引用不受影响）。**删除按钮仍然禁用**（数据包资源删了下次启动会重新导入，那是无效操作）。

### 4.4 代价（要主动讲）

**接管之后，数据包对这条景点的后续更新不会再同步过来。** 这是接管的必然代价，也是确认框里明说的。如果哪天要"跟随数据包更新"，必须先做一个还原入口。

## 五、评论模块

### 5.1 数据从哪读

| 层 | 来源 |
|---|---|
| 表 | `poi_comment`（`db/V12`），`poi_id` 直连 `poi.id`，**不带 `city_code`**（评论是用户产生的，不该随数据包重灌消失） |
| 用户 | `user_id` → `app_user.id`（复用 M8，**没有为评论另建用户体系**） |
| 昵称 | 服务端按 `user_id` 批量查 `app_user.nickname`；昵称为空时前端兜底显示"游客" |
| 游客端接口 | `GET /api/pois/{id}/comments`，只回 `APPROVED` |
| 运营端接口 | `GET /api/admin/comments`，回全部状态 |
| 前端 | `web/src/api/comments.ts` → `PoiDetail.vue` / `Resources.vue`。**`web/src/mock/` 已整目录删除** |

### 5.2 状态模型

`PENDING` / `APPROVED` / `HIDDEN`，**默认 `APPROVED`**。

选默认通过（而不是默认待审）的理由：**本项目只有一个人开发、一个演示账号**，默认待审等于"游客发完看不到自己的评论"，演示时必须再切到管理端点一次通过 —— 而审核的价值在演示里体现不出来。默认通过 + 运营可随时隐藏/删除，既满足"游客端只展示允许展示的"，又让主流程一步到位。常量上的注释写明了这个取舍。

### 5.3 三个容易写错的地方

1. **无评论时 `averageRating` 是 `null`，不是 `0`。** 0 分是"所有人都打了最低分"（一个结论），没有评论是"没有数据"（另一个结论）。前端显示「—」。
2. **列表最多 20 条，但均值和总数按全部算。** 否则评论一多，口碑评分会变成"最近 20 条的平均"。
3. **游客端 VO 刻意不含 `status` 与 `userId`。** 前者是运营态、游客不需要；后者是内部标识，没必要出网。

### 6.2 重启持久化为什么必须有"对照组"

用户原文第 6–8 步是"重启后端 → 再检查游客端 → 确认修改仍在"。**只验这一条是假通过** —— 万一 `CityPackImporter` 整体没执行，值也不会变，测试照样绿。

所以探针里加了对照组：

| 组 | 对象 | 期望 | 实测 |
|---|---|---|---|
| 实验组 | `P-SCE-001`（已接管为 ADMIN） | 管理员改的名称/地址/电话/阈值**仍在** | ✅ 全在 |
| 对照组 | `P-SCE-002`（仍是 PACK，**先手工把库里名称改成假值**） | 被数据包**覆盖回**原值 | ✅ `【对照组-重启后应被数据包覆盖】` → `兴汉胜境` |

对照组变了，才证明导入器**真的执行了删除重灌**，实验组的"没被覆盖"才有意义。

同时核对：导入日志 `资源点=42 关系=275 分类=10 体验=14 产品=16 客流统计=2520` 与基线**逐项一致**；`poi` 总行数仍是 **42**，`source='ADMIN'` 只有 1 行 —— 接管没有产生重复景点，主键没冲突。

### 6.3 浏览器验收覆盖的链路

- **A 段（管理端，19 条）**：登录 → 四标签页 → 景点页 30 行 → 已接管行的编辑按钮可点 → 数据包行的编辑也可点且 title 提示"接管" → 删除仍禁用 → **点编辑弹出接管确认框且文案说明了后果** → 表单含四个新字段 → 改名称 → 保存 → 列表更新 → `source` 标签变「运营新建」→ 删除解锁 → 切评论标签页。
- **B 段（游客端，11 条）**：详情页标题是接管后的名称 → 「详细介绍」区块渲染 → 侧栏显示地址/电话 → 无评论时是空状态文案 → **未登录提交被引导去登录** → 登录后发表 → 评论立即出现 → 署名是 `app_user` 昵称 → 5 星渲染 → **刷新后仍在** → 另一个景点显示自己的空评论（隔离）。
- **C 段（评论审核，8 条）**：管理端看到该评论 → 显示所属景点名 → 默认「已通过」→ 有隐藏/删除 → 隐藏后状态变更 → **游客端不再显示** → 删除前有确认框 → 删除后列表里没有了。

### 6.4 顺带发现并修掉的真 bug（★ 这是本轮最有价值的一条）

**现象**：接口层 45/45 全绿、`vue-tsc` EXIT=0，但浏览器里 `/poi/P-SCE-001` **纯白**。

**根因**：`PoiDetail.vue` 里那个 `watch(() => poi.value?.id, ..., { immediate: true })` 在 setup 同步阶段就会先跑一次，此时 `poi` 还没加载、`id` 是 `undefined`，回调走到 `commentData.value = null` 这一支 —— 而 `commentData` 声明在它**后面** 100 多行，于是：

```
ReferenceError: Cannot access 'commentData' before initialization
```

Vue 的 setup 一旦抛错，整个组件什么都不渲染。

**修法**：把评论那一整块（`commentData` / `comments` / `commentTotal` / `averageRating` / `loadComments`）**整体上移到那个 watch 之前**，并在块首写明原因。

**为什么这一条重要**：`vue-tsc` 抓不到它（不是类型错误），接口探针也抓不到它（后端确实是对的）。**只有真在浏览器里打开这个页面才会暴露。** 这正是"不要只做表面功能"要防的东西。

## 十一、游客端评论区 UI 改造（2026-09-28 续做）

### 根因不是"样式不好看"，是一个悬空的类名

`PoiDetail.vue` 的 `<textarea>` 写着 `class="field field--area"`，而**这两个类在本组件里从未定义过**。
`.field` 只存在于 `admin/Resources.vue` 与 `admin/Media.vue` 的 `<style scoped>` 里，而且那套是**管理端深色主题**、用了 portal 侧不存在的 `--line-strong`。

scoped 样式不跨组件生效 → textarea 一直吃浏览器默认样式：`cols=20` 的窄框（实测只占表单宽度约 30%）、方角、系统字体。
这就是"输入框窄得和卡片留白完全不匹配、且与整体风格不统一"的根源，不是配色或间距没调好。

它能长期存在，是因为两道检查都漏掉了它：`vue-tsc` **不报**（未知 class 不是类型错误），而全仓 `grep '\.field'` **能搜到** —— 只是在错的文件里。

### 改法

- 输入框改用**自己的类** `.cfield`（不再借用别处的名字），按 portal 纸感令牌写：满宽 / `min-height: 132px` / 16px 内边距 / 6px 圆角 / `--paper` 底色 / focus 时 `--brand-500` 描边 + `--brand-50` 光晕 / `resize: vertical`。
- 表单重构成四层：标题行（18px 标题 + 右侧"点击星星打分"）→ 星级行（26px 星 + 档位文案）→ 输入框 → 底部（左侧提示 / 右侧"字数 + 发表按钮"）。
- 星级加**悬停预览**：`hoverRating` 让鼠标划过时先看"这一档是什么评价"（很差 / 一般 / 还不错 / 很好 / 非常棒），移开回到已选档；`aria-pressed` 只表达已选值，预览不改数据。
- 字数统计显示 `已写 / 500`，超过 450 字转提醒色。
- 评论卡片加**首字头像**（不引图片资源，也不依赖一个并不存在的头像字段），卡片改 `--paper-2` + hairline 边框，正文 `white-space: pre-wrap`。
- 空状态从"大片留白里飘一行小字"改成虚线卡片 + 一个克制的引号标记。
- 有评论时区块标题右侧显示 `均分 + 星条 + N 条评价`；**无评论仍只显示"暂无评价"**（不显示 0.0 —— 与"不显示假评论"是同一条纪律）。

### ★ 两处必须守住的约束，否则会把历史验收改瞎

1. `.reviews__empty` 的 `textContent` **只**含那句文案 —— 装饰标记挂在**兄弟节点**上。历史探针（`accept_m10b_ui.mjs` 的 B5 / C6）是按 `textContent.trim()` 逐字比对的。
2. 保留 `.cform textarea`、`.cform__foot button`、`.stars__btn`（5 个，第 5 个 = 5 星）、`.reviews .review`、`.review__stars`、`.review__text` 这些选择器。按钮由 `@click` 改为 `type="submit"` + `@submit.prevent`，但仍在 `.cform__foot` 内、文案仍是「发表评价」。
