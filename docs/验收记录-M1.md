# M1 统一资源（POI）· 验收记录

> 验收日期：2026-09-23 · 结论：**通过**
> 模块范围：`db/V1__m1_resource.sql` → Spring Boot 接口 → 前端探索页与详情页 → 联调

## 一、模块职责边界

**做**：一张 `poi` 表承载景区 / 乡村 / 餐饮 / 住宿 / 交通 / 购物六类资源（靠 `business_type` 区分）；
`poi_relation` 把孤立资源点变成可查询的网络；City Pack 导入器把 `citypack/<city>/*.json` 灌进库。

**不做**：承载统计（M5）、订单（M6）、行程（M4）、体验与产品（M2）。
`pois.json` 之外的三个数据文件 M1 一行都没读——那是 M2 的范围。

## 五、前端改动

| 改动 | 原因 |
|---|---|
| 新增 `api/http.ts` | 统一处理三种失败：连不上后端 / 路径写错 / 业务失败，各自给出可执行提示 |
| `api/citypack.ts` 的 `getMeta` `getPois` 切到后端 | M1 的数据源落点。函数名不变，所以首页与探索页代码一行没动 |
| 新增 `getPoiDetail` | 详情页改读后端的四组关系 |
| `PoiDetail.vue` 的关系改由后端提供 | 原来前端用 Haversine 自己算距离，现在关系由后端生成——换城市后关系网络自动重建 |
| `PoiDetail.vue` 加 `watch(route.params.id)` | 从「周边联动」点进另一个资源时组件被复用，不重新取数会停在上一个资源上 |
| `fmtKm()` 距离文案 | 有 3 组资源坐标相同（客栈就在古镇里、民宿就在景区内），距离 0km 直接显示 "0 km" 会被当成 bug，改说"同址" |
| `loadDetail` 把错误码 1001 转成"未找到" | 链接过期、资源下架是正常产品状态，不该给用户看一行技术性红字 |

**未改**：`Explore.vue`、`Home.vue` 一行未动（它们调 `getCityPack()`，数据源在 API 层切换）。

**验收过程中修掉的两个问题**

1. **`support` 里混进了乡村点**。原规则是"不同业态且距离 ≤20km"，导致景区详情页的
   "同一片区域里的吃、住、行"里出现乡村点，文案和内容对不上。
   改为只把吃住行购作为配套目标（`SUPPORT_TYPES`）——景区与乡村是"目的地"，
   它们之间的关系由 `DIVERSION` 承担、景区之间由 `NEARBY` 承担。SUPPORT 由 114 条降到 54 条。
2. **资源不存在时走了错误态**。后端返回 1001 时前端显示红色错误框，
   对"链接过期"这种正常情况是过度反应。改为把 1001 归入"未找到"空状态。

## 七、已知问题

1. **`ancient` 场景插画在超宽 Hero 里被裁成横带**。
   `SceneArt` 用 `preserveAspectRatio="xMidYMid slice"` 填满容器并裁切，
   Hero 的宽高比约 4:1，而插画按 16:10 设计，居中裁切后只剩屋檐的几条横带。
   `qinling` / `terrace` / `river` 是横向山峦与水波，裁切后依然成立（首页 Hero 效果正常），
   只有 `ancient` 的横向建筑结构会露馅。
   *影响范围*：使用 `ancient` 的资源详情页 Hero。
   *建议方案*：给 `ancient` 补一层远山背景，让超宽裁切后仍有纵向层次。
   属前端基座（M0）的视觉调整，未在 M1 内改动，待确认。

2. **`P-FOOD-001` 汉中热面皮的坐标用了城市中心点（107.02, 33.07）**。
   它是唯一一个用中心点占位的资源，导致它与市区其他资源的距离偏近。
   数据包层面的小瑕疵，不影响功能。
